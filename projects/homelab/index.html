Homelab

My homelab is a small Proxmox environment that I use to explore virtualization, self-hosting, automation, security, and infrastructure as code. It began as a way to gain more experience with Proxmox and has grown into a practical place to run useful services and experiment outside of a production environment.

Overview

I started the lab in May 2025 on a single ThinkPad T14. Working within limited hardware has encouraged me to keep the environment deliberate and efficient while still giving me room to learn.

  • Background and evolution covers how the lab began and how it evolved.
  • First-generation ThinkPad setup preserves the earlier hardware, VM layout, and services.
  • Current architecture describes the current Xeon-based environment and its design.

Current architecture

Proxmox provides the virtualization layer for the lab. The current environment separates public access, management, monitoring, development, application hosting, game hosting, and Kubernetes experimentation into deliberate roles. The current architecture describes those boundaries in detail.

Hosted services

Most applications run as Docker Compose projects on a dedicated application host, while the edge VM controls access to services that are deliberately published.

Access and routing

  • Vaultwarden provides password management.
  • Apache Guacamole provides browser-based remote access.
  • Caddy on the edge VM routes approved web traffic to the appropriate services.

Container maintenance

  • Watchtower checks for container-image updates.

Security

  • Network segmentation and edge firewall policy limit access between management and service workloads.

Automation and infrastructure as code

I use Ansible for guest configuration and Terraform to define VM infrastructure. Kubernetes is an on-demand learning environment, while current Compose projects remain in version control so their configuration is not tied only to a running host.

Development environment

One always-on virtual machine serves as a development environment. Experimenting with Vim, Neovim, and LazyVim taught me to prefer a simpler, maintainable configuration over endless customization.
